## Nhóm 1 - Vá bug & an toàn (BẮT BUỘC, làm trước, rủi ro thấp)

Sắp theo thứ tự tăng dần độ phức tạp. Mỗi mục xong chạy pytest module liên quan.

### 1.1 - Cảnh báo `def` thay vì `async def` cho endpoint code-first (backlog #9)

- File: `xime/adapters/grpc/codefirst/_builder.py`, method `_resolve()`
- Vấn đề: endpoint viết nhầm `def` -> server lên bình thường, mọi RPC crash
  runtime với `TypeError: object NoneType can't be used in 'await' expression`.
- Sửa: thêm `inspect.iscoroutinefunction(func)`; không async -> ném
  `StartupException` nêu rõ controller + method.
- Test: case startup-fail trong `tests_temp/grpc_codefirst/`.

### 1.2 - Interceptor lỗi abort hai lần (note data-service #2)

- File: `xime/adapters/grpc/interceptors/_error.py`, `_wrap_unary` (dòng ~67) và
  `_wrap_streaming` (dòng ~89)
- Vấn đề (đã verify): `grpc.aio.AbortError` MRO là
  `AbortError -> BaseError -> Exception`, KHÔNG kế thừa `grpc.RpcError`. Khi một
  custom interceptor innermost đã gọi `context.abort()`, `AbortError` bay ra
  ngoài, nhánh `if isinstance(exc, grpc.RpcError): raise` không khớp -> abort lần
  hai. Kết quả về client vẫn đúng (grpc giữ status lần đầu) nhưng có abort thừa.
- Sửa: hai nhánh except thành
  `if isinstance(exc, (grpc.RpcError, grpc.aio.AbortError)): raise`.
- Test: `tests_temp/grpc/test_interceptors.py` - custom interceptor abort, assert
  chỉ một lần abort, status/metadata giữ nguyên.

### 1.3 - Default lộ `str(exc)` ra client (note data-service #1a)

- File: `xime/adapters/grpc/interceptors/_error.py` (dòng ~71, ~94)
- Vấn đề: exception CHƯA map (rơi vào `INTERNAL`) ném nguyên `str(exc)` - message
  nội bộ - về client. Lo bảo mật.
- Sửa: lỗi đã map giữ message; lỗi không map -> trả message chung chung
  (vd `"Internal server error"`), KHÔNG phải `str(exc)`. Vẫn log đầy đủ phía
  server.
- Test: assert client nhận message generic khi exception ngoài mappings.
- Ghi chú: đây chỉ là nửa "lộ str(exc)" của note #1. Nửa còn lại - error catalog
  visibility-aware dùng chung (#1b) - là quyết định kiến trúc, ĐẨY sang 0.4.

### 1.4 - `_dynamic_channel()` không thread-safe khi cert rotate (backlog #7)

- File: `xime/adapters/grpc/client/_channel.py`, method `_dynamic_channel()`
- Vấn đề: 2+ coroutine đồng thời thấy version đổi -> cùng tạo channel mới,
  channel đầu bị ghi đè và leak (không vào `_retired`).
- Sửa: bọc đoạn check-and-replace bằng `asyncio.Lock`, double-check version sau
  khi vào lock.
- Test: `tests_temp/grpc_client/test_channel_rotation.py` - concurrent rotate,
  assert không leak channel.

### 1.5 - `wire_dynamic_certificates()` hardcode `server_id="default"` (backlog #8)

- File: `xime/adapters/grpc/client/_config.py`
- Vấn đề: client mTLS động luôn lấy provider từ server `"default"`, chặn kịch bản
  multi-server.
- Sửa: cho phép truyền `server_id` qua `configure_grpc_clients()` (hoặc per-client
  config), mặc định `"default"` để giữ tương thích.
- Test: `tests_temp/grpc_client/` - wire client tới provider của server
  non-default.

## Nhóm 2 - Hoàn tất gRPC client (resilience)

### 2.1 - Retry policy trong YAML

- Nơi: schema `grpc.clients.<id>.retry`, cắm vào `XimeGrpcChannel`.
- Nội dung: `max_attempts`, `backoff` (initial/max/multiplier), danh sách status
  retry (mặc định chỉ `UNAVAILABLE`). Tận dụng `RemoteServiceUnavailable` /
  `RemoteCallTimeout` đã có.
- Lưu ý an toàn: mặc định chỉ retry trên `UNAVAILABLE` để không nhân đôi tác dụng
  phụ với call không idempotent.
- Test: server flaky trả `UNAVAILABLE` rồi OK -> retry thành công; vượt max ->
  ném typed error.

> Phần "sinh SDK từ ContractModel" là tính năng fidelity mới -> ĐẨY sang 0.4.

# PHẦN B - ⛔⛔ CẠM BẪY SỐ MỘT: hệ tệp

**Chủ dự án nói: cùng MÁY, khác HỆ ĐIỀU HÀNH.** Nên rất có thể bạn sẽ thấy repo qua
một phân vùng Windows được mount.

> ⛔⛔ **NẾU BẠN CHẠY ĐO TRÊN MỘT PHÂN VÙNG NTFS ĐƯỢC MOUNT, MỌI PHÉP ĐO QUYỀN FILE
> Ở PHẦN D LÀ VÔ NGHĨA.**

`ntfs-3g` gán quyền POSIX **giả** cho toàn bộ phân vùng theo tuỳ chọn mount
(`fmask`/`dmask`), không theo thứ chương trình thật sự đặt. `chmod` trên đó hoặc
không có tác dụng, hoặc có tác dụng giả. Đo `C1` (quyền file LMDB) hay `C2` (quyền
unix socket) ở đó là **đang đo một tuỳ chọn mount**, và kết quả trông y hệt một phép
đo thật.

**Kiểm bắt buộc trước khi đo bất cứ thứ gì ở phần D:**

```bash
# 1. Repo đang nằm trên hệ tệp gì
df -T .                       # cột Type PHẢI là ext4/btrfs/xfs..., KHÔNG được là fuseblk/ntfs
mount | grep -i "$(df --output=source . | tail -1)"

# 2. Đối chứng dương: chmod có thật sự ăn không
umask 022
touch /tmp/_probe && chmod 0600 /tmp/_probe && stat -c '%a %n' /tmp/_probe   # phải in "600"
touch ./_probe  && chmod 0600 ./_probe  && stat -c '%a %n' ./_probe          # phải in "600"
rm -f /tmp/_probe ./_probe
```

Dòng thứ hai không in `600` -> **dừng lại**, chép repo sang một hệ tệp Linux thật
(`cp -a` sang `~/xime-framework`) rồi làm lại từ đầu. Ghi vào kết quả là bạn đã chép.

⚠ Kèm hai chỗ nữa cùng gốc: `/dev/shm` phải là **tmpfs** thật
(`mount | grep /dev/shm`), và kho LMDB phải đặt trên hệ tệp Linux
(`lmdb.path: /tmp/...`), không đặt trên phân vùng mount.

## L-01 - File kho LMDB có world-readable không

**Câu hỏi:** sau khi một `Store` ghi một khoá, file `.mdb` và file khoá của nó mang
quyền gì?

**Vì sao Windows mù:** quyền POSIX không tồn tại ở đó; `os.stat().st_mode` trên
Windows luôn cho `0o666`/`0o444` bất kể code làm gì.

**Chạy:**

```bash
umask 022
rm -rf /tmp/xime-l01 && mkdir -p /tmp/xime-l01

python - <<'PY'
import asyncio, stat
from pathlib import Path
from xime.starters.lmdb import LmdbEnvironment, LmdbConfig, CounterStore

class HamNhip(CounterStore, name="ham-nhip", ttl=900, parts=2):
    pass

async def main():
    env = LmdbEnvironment(LmdbConfig(path="/tmp/xime-l01"))
    await HamNhip(env).incr("nguoi-dung-that")
    env.close()

asyncio.run(main())
for p in sorted(Path("/tmp/xime-l01").rglob("*")):
    print(f"{stat.filemode(p.stat().st_mode)}  {oct(p.stat().st_mode & 0o777)}  {p}")
PY
```

⚠ Chữ ký `LmdbEnvironment(...)` / `LmdbConfig(...)` có thể khác - đọc
`xime/starters/lmdb/__init__.py` rồi chỉnh. Phần đáng giữ là **ghi một khoá rồi
`stat` mọi file sinh ra**.

**ĐẠT:** mọi file `0600` hoặc chặt hơn, mọi thư mục `0700` hoặc chặt hơn.
**VI PHẠM:** bất kỳ file nào có bit đọc của `group` hoặc `other`.

**Đối chứng dương:**

```bash
touch /tmp/xime-l01/doi-chung && chmod 0644 /tmp/xime-l01/doi-chung
# chạy lại đoạn stat: PHẢI in ra -rw-r--r-- cho file này.
# Không in ra thì phép đo hỏng, đừng tin kết quả ở trên.
```

## L-02 - Unix socket cha bind có world-accessible trong cửa sổ khởi động không

**Câu hỏi:** giữa lúc cha `bind()` + `listen()` và lúc con gọi `secure_socket_file()`,
file socket mang quyền gì, và cửa sổ đó dài bao nhiêu?

**Vì sao Windows mù:** quyền POSIX vô nghĩa, và `SO_PEERCRED` - nửa còn lại của mô
hình bảo mật - chỉ có trên Linux.

**Chạy:** cần một app có `SocketAdapter` chạy dưới `share_load()`.

```bash
cd /tmp && rm -rf l02 && xime init l02 && cd l02
# 1. thêm SocketAdapter vào main.py (app.use(SocketAdapter()))
# 2. đổi resources/application.yml sang khối processes: với 2 tiến trình, khai
#    socket: { rpc: { path: /tmp/l02/app.sock, shared: true } }
# 3. thêm một `await asyncio.sleep(20)` vào một post_construct để KÉO DÀI cửa sổ
```

Đo ở terminal khác, **bật TRƯỚC khi khởi động app**:

```bash
while true; do
  [ -e /tmp/l02/app.sock ] && stat -c '%y %A %a %U:%G' /tmp/l02/app.sock
  sleep 0.05
done | uniq -f2
```

**ĐẠT:** dòng đầu tiên xuất hiện đã là `srw-------` (0600).
**VI PHẠM:** có ít nhất một dòng rộng hơn 0600 trước khi nó đổi thành 0600. Ghi lại
khoảng cách thời gian giữa dòng đầu và dòng 0600 - **đó là độ dài cửa sổ**.

**Đo thêm nếu đã VI PHẠM** - user khác có kết nối được trong cửa sổ đó không:

```bash
sudo -u nobody python3 -c "
import socket
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.connect('/tmp/l02/app.sock')
print('KET NOI DUOC bang user khac')"
```

**Đối chứng dương:** chạy chính lệnh đó **sau** khi app đã ổn định. Nó phải cho
`PermissionError`. Không cho thì phép đo không phân biệt được hai trạng thái.

## L-05 - `SharedMemory` của Python tạo file `/dev/shm` với quyền gì

Đây là **nền của C1 và C2 ở tầng bus**: bus là **kênh điều khiển** (`__xime__`) chở
lệnh thăng cấp primary, nên ai ghi được vào nó thì điều khiển được vòng đời cụm.

```bash
python -c "
from multiprocessing.shared_memory import SharedMemory
import time
b = SharedMemory(name='xime-l05', create=True, size=4096)
print('da tao, cho 30s'); time.sleep(30); b.close(); b.unlink()" &
sleep 1
stat -c '%A %a %U:%G  %n' /dev/shm/xime-l05

sudo -u nobody head -c 8 /dev/shm/xime-l05 >/dev/null \
  && echo ">> USER KHAC DOC DUOC" || echo ">> user khac khong doc duoc"
sudo -u nobody dd if=/dev/zero of=/dev/shm/xime-l05 bs=1 count=1 conv=notrunc 2>/dev/null \
  && echo ">> USER KHAC GHI DUOC - kenh dieu khien bi nguoi ngoai ghi duoc" \
  || echo ">> user khac khong ghi duoc"
```

## E.2. 🔴 CAO

### C1 - `lmdb.open()` không truyền `mode=`

**Ở đâu:** `xime/starters/lmdb/_env.py:169`. `py-lmdb` mặc định `mode=0o755`; với
`subdir=False` thì file dữ liệu và file khoá tạo theo `mode & ~umask`, ra **0644**
với umask 022. Thư mục cha cũng vậy.

**Nội dung kho:** hãm nhịp đăng nhập, thử thách passkey, chống lặp.

**Vì sao Cao:** repo đã ra quyết định ngược lại cho cùng loại dữ liệu và ghi lý do
vào code - `xime/starters/localfs/_storage.py:94` dùng `0o600`/`0o700` (từ phát hiện
F13 của kiểm toán 0.7). Chuẩn có sẵn trong nhà, mảng mới không đi theo.

**Vá:** thêm `mode=0o600` vào `lmdb.open`; sau `mkdir` thì `os.chmod(dir, 0o700)`;
cho người vận hành khai qua `lmdb.file_mode` / `lmdb.dir_mode` đúng khuôn
`storage.local.*`. ⚠ `mkdir(mode=)` bị umask cắt nên **phải `chmod` lại sau khi
tạo**, đừng chỉ truyền tham số.

**Đối chứng:** gỡ `mode=` ra thì test canh quyền file phải đỏ. Test đi thành cặp:
mặc định phải là 0600 · giá trị khai trong cấu hình phải được tôn trọng.

### C2 - Cha bind unix socket rồi `listen()` mà không chmod

**Ở đâu:** `xime/core/bootstrap/_supervisor.py:400-424` (`_bind_unix`).
`grep -c chmod` trong file đó ra **0**.

Con **có** chmod (`secure_socket_file()` gọi vô điều kiện ở
`xime/adapters/socket/_adapter.py:163`), nên đây là một **CỬA SỔ**, không phải lỗ
vĩnh viễn. Nhưng cửa sổ phủ: import lại `main.py`, dựng DI, mở pool, lấy cert, chạy
`run_once()` (migration). Framework tự khai nó có thể dài **60 giây**
(`_RUN_ONCE_WAIT = 60.0`, `STARTUP_GRACE_SECONDS = 60.0`).

Và `allowed_uids` mặc định `()`, với `authorize_peer` ghi rõ *"Whitelist rỗng =
chấp nhận mọi UID; lúc đó dựa hoàn toàn vào file permission"* - tức quyền file là
chốt chặn **duy nhất**.

Đây là **hồi quy do 0.8 sinh ra**: một tiến trình thì bind và chmod là hai dòng liền
nhau.

**Vá:** `os.chmod(spec.path, 0o600)` ngay sau `bind()` và **trước** `listen()`. Cha
không biết `permission` đã cấu hình (nó ở `socket.<id>.permission`, mà cha không
dựng DI) - thứ tự đúng là **chặt trước, nới sau**.

**Đối chứng:** test soi quyền file **ngay sau `_bind_unix`**, không phải sau khi con
đã chạy. Gỡ `chmod` ra thì test phải đỏ.

### C3 - Thăng cấp primary không chạm tới `RefDataArena` ⭐ NẶNG NHẤT

**Ở đâu:** `xime/core/bootstrap/application.py:695` (`_accept_promotion`) và
`xime/core/refdata/_arena.py:118`.

Cờ *"tôi có phải primary"* nằm ở **hai chỗ**, chỉ một chỗ được cập nhật:

| Nơi giữ cờ | Đổi khi thăng cấp? |
|---|---|
| `Application._is_primary` | ✅ `_accept_promotion` đặt `True` |
| `RefDataArena._primary` | ⛔ **không có setter nào tồn tại** |

`grep -n "_primary" xime/core/refdata/_arena.py` ra đúng hai dòng: gán trong
`__init__` (118), đọc trong property (211). Mà `RefData.publish()` hỏi **đúng cái cờ
không được cập nhật** (`_refdata.py:335`).

**Đo được trên Windows:**

```text
sau thang cap : Application._is_primary = True
                arena.primary            = False
  -> publish VAN BI CHAN: RefDataNotWriterError
```

**Hậu quả:** primary mới **không bao giờ cập nhật được khoá JWT nữa** - ca dùng số
một của `RefData`. Ngày Trust xoay khoá, mọi token mang `kid` mới verify hỏng ở
toàn cụm.

⚠ **Triệu chứng nói ngược sự thật:** cha log *"took the primary role"*, `/healthz`
trả `primary: true`, `PROMOTED` đã báo. Chỉ một dòng lỗi nói *"called from a
non-primary process"*. Người đọc sẽ đi tìm lỗi ở cơ chế thăng cấp.

**Vá:** một nguồn sự thật, không phải hai. Hoặc `RefDataArena` đọc cờ qua một
callable từ `Application`, hoặc `_accept_promotion` gọi `self._refdata.promote()`.
⚠ **Nhánh TỪ CHỐI vai cũng phải quay cờ về**, nếu không một con từ chối vai lại
publish được.

**Đối chứng:** test đi **thành cặp** - thăng cấp xong thì `publish()` **chạy**; từ
chối vai xong thì `publish()` **bị chặn**. Chỉ có test một vế thì cách sửa sai *"cho
publish luôn"* cũng qua được.
